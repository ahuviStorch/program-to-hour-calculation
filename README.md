# מעקב שעות עבודה

אפליקציית מעקב שעות אישית: ניהול נושאים, התחלה/השהיה של מעקב, היסטוריית רשומות
וסה"כ זמן לכל נושא. הנתונים נשמרים בקובץ JSON מקומי בשרת וממשיכים להתקיים גם אחרי
הפעלה מחדש.

- **שרת:** Node.js + Express (שמירה לקובץ JSON, סגירה אוטומטית של סשנים ארוכים).
- **לקוח:** React + Vite + Tailwind CSS (ממשק עברית מימין לשמאל).

---

## דרישות מוקדמות

- Node.js גרסה 22.9 ומעלה (נבדק עם 24.x) ו-npm.
- אין צורך במסד נתונים או בכלים נוספים.

בדיקת הגרסה:

```bash
node -v
npm -v
```

---

## התקנה

1. העתיקו את קובץ הדוגמה של ההגדרות:

   ```bash
   cp .env.example .env
   ```

2. פתחו את `.env` ו**החליפו את `DELETE_PIN`** לערך משלכם (לפחות 4 תווים).
   השרת מסרב לעלות אם ה-PIN חסר או קצר מדי, ומציג אזהרה אם נשאר קוד
   ברירת המחדל של הדוגמה.

3. התקינו את התלויות (פעם אחת):

   ```bash
   npm install
   ```

## הרצה בסביבת פיתוח

```bash
npm run dev
```

הפקודה מרימה שני תהליכים במקביל:

| תהליך | כתובת | תיאור |
|---|---|---|
|לקוח (Vite)|http://localhost:5173|הממשק — זה הכתובת שפותחים בדפדפן|
|שרת API|http://127.0.0.1:3001|בקשות `/api/...`|

בזמן פיתוח, Vite מעביר אוטומטית כל בקשה ל-`/api` אל השרת (ראו `proxy`
ב-[client/vite.config.js](client/vite.config.js)) — אין צורך בשום הגדרה נוספת.
שינויים בקוד השרת ובקוד הלקוח נטענים מחדש אוטומטית.

## הרצה "כמו בשרת" (פורט יחיד)

```bash
npm run build && npm start
```

(`npm start` בונה את הלקוח ואז מריץ את השרת.) השרת מגיש את הקבצים הבנויים
ואת ה-API מאותו פורט: http://localhost:3001 — כתובת אחת לכל האפליקציה.

אם הלקוח כבר בנוי ואתם רק רוצים להריץ את השרת: `npm run serve`.

## הגדרות (`‎.env`)

| משתנה | ברירת מחדל | משמעות |
|---|---|---|
| `PORT` | `3001` | הפורט של ה-API (וגם של האתר הבנוי) |
| `DATA_FILE` | `data/db.json` | מיקום קובץ הנתונים (יחסי לתיקיית הפרויקט) |
| `DELETE_PIN` | — | קוד למחיקה (4 תווים לפחות). חובה להגדיר. |
| `AUTO_CLOSE_HOURS` | `6` | משך מרבי של סשן פתוח בשעות |
| `SWEEP_MINUTES` | `15` | תדירות סריקת הרקע שסוגרת סשנים שפג תוקפם |
| `PIN_MAX_FAILS` | `5` | ניסיונות PIN שגויים לפני נעילה זמנית |
| `PIN_LOCK_MS` | `600000` | משך הנעילה (10 דקות) |

לאחר שינוי ב-`.env` יש להפעיל מחדש את השרת.

## איך עובד המעקב

- **רשומה פתוחה** = רשומה שיש לה רק שעת התחלה. הנושא נחשב "פעיל".
- **השהיה** סוגרת את הרשומה (שעת סיום = הרגע הנוכחי), ולכן כל התחלה/השהיה
  יוצרת שורה נפרדת בהיסטוריה. התחלה מחדש ממשיכה לצבור על אותו נושא.
- **סגירה אוטומטית:** כדי שלא ייווצרו רשומות "פתוחות לנצח" כששוכחים להשהות,
  רשומה שעברה את `AUTO_CLOSE_HOURS` נסגרת לבד, וזמנה מוגבל בדיוק למשך המקסימלי.
  הסגירה מתבצעת בכל קריאת נתונים, בנוסף לסריקת רקע כל `SWEEP_MINUTES` דקות
  (וגם בעליית השרת). רשומות אלה מסומנות בהיסטוריה כ"נסגר אוטומטית".
- השרת הוא מקור האמת היחיד: סה"כ השעות מחושב בכל בקשה, והלקוח רק מציג
  שעון "חי" שמתקדם בין הרענונים (כל 30 שניות ובחזרה לחלון).

## מחיקה וקוד PIN

- מחיקת רשומה בודדת ומחיקת נושא (עם כל ההיסטוריה שלו) דורשות קוד PIN.
- **נושא פעיל לא נמחק לפני אישור חוזר** — מוצגת אזהרה שהזמן של הסשן הנוכחי לא יישמר.
- **רשומה פעילה אינה ניתנת למחיקה** — יש להשהות אותה קודם.
- ה-PIN נשלח לשרת בכותרת הבקשה בלבד, נבדק בצד השרת, **אינו נשמר בדפדפן**
  ואינו מופיע בלוגים. אחרי טעינת העמוד מחדש הוא נדרש שוב.
- אחרי `PIN_MAX_FAILS` ניסיונות שגויים מאותו מחשב יש נעילה זמנית של
  `PIN_LOCK_MS`; החלון מציג ספירה לאחור עד לפתיחה מחדש.

**שימו לב:** ה-PIN מגן על מחיקה מתוך הממשק. מי שיש לו גישה ישירה לקבצי השרת
יכול לערוך או למחוק את `data/db.json` — שמרו את הקובץ במקום מסודר, וקיימו גיבוי.

## קובץ הנתונים

- הנתונים נשמרים ב-`data/db.json` (או לפי `DATA_FILE`).
- **שמירה אטומית:** כל שינוי נכתב לקובץ זמני, מסונכרן לדיסק ומוחלף במקום —
  לכן הפסקת חשמל או קריסה באמצע כתיבה אינן משחיתות נתונים קיימים.
- **גיבוי אוטומטי:** לפני כל החלפה נשמר העותק הקודם ב-`db.json.bak`.
- **שחזור:** אם הקובץ הראשי פגום, השרת מעביר אותו ל-`db.json.corrupt-<timestamp>`
  וטוען את `.bak`; אם גם הוא פגום, השרת מתחיל מקובץ ריק (בלי למחוק את הפגומים).
- כדי לגבות את הנתונים: עצרו את השרת והעתיקו את תיקיית `data/`.

## מבנה הפרויקט

```
server/
  index.js        הרכבת האפליקציה, סריקת הרקע, הגשת הלקוח הבנוי
  config.js       קריאה ובדיקה של משתני הסביבה
  db.js           טעינה, שמירה אטומית, התאוששות מקובץ פגום
  model.js        לוגיקה עסקית: התחלה/השהיה/סה"כ/סגירה אוטומטית
  pin.js          אימות PIN עם הגבלת ניסיונות
  errors.js       טיפול אחיד בשגיאות
  routes/         topics.js, sessions.js, history.js
client/
  src/api/client.js        קריאות לשרת
  src/hooks/               useTracker (מצב), useNow (שעון), usePinPrompt (חלון PIN)
  src/components/          רכיבי הממשק
  src/lib/format.js        עיצוב תאריכים ומשכים
data/             קובץ הנתונים והגיבוי
```

כל קבצי השרת והלקוח כוללים הערות בעברית המסבירות את הלוגיקה.

## בדיקת ה-API ידנית

כשהשרת פעיל:

```bash
curl http://127.0.0.1:3001/api/state
curl -X POST http://127.0.0.1:3001/api/topics \
  -H "Content-Type: application/json" -d '{"name":"נושא 1"}'
```

בקשות מחיקה דורשות כותרת: `-H "x-delete-pin: <הקוד שלכם>"`.

## פתרון תקלות

- **השרת לא עולה / "DELETE_PIN" שגוי** — ודאו שיצרתם `.env` (העתקה מ-`.env.example`)
  וש-PIN באורך מספיק. הודעת השגיאה במסוף מפרטת מה חסר.
- **"אין חיבור לשרת" בדפדפן** — ודאו שהתהליכים של `npm run dev` רצים, ושפורט 3001
  פנוי. הפרוקסי של Vite קורא את `PORT` מ-`.env` אוטומטית, ולכן אין צורך
  בהגדרה נוספת.
- **שגיאה בהתקנה של Tailwind v4** (חבילת בינארי מקומית של Windows) — אם הרשת
  המסוננת חוסמת אותה, אפשר לעבור ל-Tailwind v3.4 עם `postcss` ו-`autoprefixer`
  (תלויות JavaScript בלבד); יש להוסיף `tailwind.config.js` ולהחליף את
  `@import "tailwindcss"` ב-`@tailwind base/components/utilities` ב-`client/src/index.css`.
- **Windows: שגיאה בכתיבת `db.json`** — אם הפרויקט נמצא בתיקייה שמסתנכרנת
  (למשל OneDrive), התוכנה עלולה לנעול את הקובץ לרגע. השרת מנסה שוב אוטומטית;
  אם הבעיה חוזרת, העבירו את הפרויקט לתיקייה מקומית שאינה מסונכרנת.
